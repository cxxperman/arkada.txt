# arkada.txt

Arkada — часть dev.txt™ для клиента Steam. Здесь две вещи, и каждая работает без другой:

- **Тема** — окна Steam в виде приложения Windows 11 (Mica, слои Fluent) на токенах dev.txt: те же цвета, скругления, шрифт и движение, что в Kapsula, Aura и core.txt.
- **Плагин** — рассказывает остальным приложениям dev.txt на этом компьютере, что происходит в Steam: какая игра запущена, что скачивается, кто зовёт играть.

Обе ставятся в [Millennium](https://github.com/SteamClientHomebrew/Millennium) — неофициальную надстройку над клиентом Steam. Без Millennium Arkada не работает.

> **Millennium — неофициальная модификация клиента Steam.** Valve её не поддерживает и не одобряет; ставится она на свой страх и риск. После обновления Steam тема или плагин могут частично перестать работать — сам Steam от этого не ломается: достаточно выключить их в настройках Millennium.

> **В настоящем Steam ничего из этого не запускалось.** Проверено всё, что можно проверить без Steam; что именно — в разделах «Проверки» и «Что не проверено».

## Тема

Папка [theme](theme) — готовая тема, её можно ставить как есть. Стили пишутся в [theme/src](theme/src), а `tools/build.js` собирает из них файлы, которые грузит Millennium.

| Файл | Что это |
|---|---|
| [theme/skin.json](theme/skin.json) | описание темы для Millennium: какие файлы в какие окна и восемь настроек |
| [theme/src](theme/src) | исходники стилей — правятся здесь |
| [theme/src/base.css](theme/src/base.css) | общее для всех окон: переменные Steam, фон Mica, кнопки, поля, диалоги, кольцо фокуса, контекстные и выпадающие меню, меню уведомлений, тосты, подсказки, мини-профиль |
| [theme/src/libraryroot.custom.css](theme/src/libraryroot.custom.css) | главное окно: шапка, левый список библиотеки, главная библиотеки, страница игры, нижняя панель, загрузки |
| [theme/src/friends.custom.css](theme/src/friends.custom.css) | список друзей и чат |
| [theme/src/webkit.css](theme/src/webkit.css) | страницы магазина и сообщества: полосы прокрутки, навигация магазина, главные кнопки |
| [theme/src/options/layout-sidebar.css](theme/src/options/layout-sidebar.css) | настройка «Раскладка: боковая панель» |
| [theme/src/options/transparency.css](theme/src/options/transparency.css) | настройка «Прозрачность окна» (с плагином Window Styler / DWMX) |
| `theme/src/options/hide-*.css` | настройки «Что нового», «Добавить новый раздел», «Строка адреса» |
| `theme/*.css`, `theme/options/layout-sidebar.css`, `theme/options/transparency.css`, `theme/options/hide-*.css` | собранные из `theme/src` файлы. Пишет `tools/build.js`, руками не правятся |
| [theme/tokens.css](theme/tokens.css) | токены kit.txt, переменные `--dt-…`. Пишет `tools/build.js`, руками не правится |
| [theme/options](theme/options) | файлы настроек темы: акценты (пишет `tools/build.js`), прямые углы, шрифт |
| [steam-classes.json](steam-classes.json) | снимок классов клиента Steam: читаемое имя → хеш. Пишет `tools/steam-classes.js` |

Настройки темы (в Millennium: «Темы» → Arkada → настройки):

- **Акцент** — «Как в dev.txt» или любой цвет палитры токенов.
- **Прозрачность окна** — да (по умолчанию) или нет. Сквозь окна Steam виден размытый рабочий стол, как в приложениях Windows 11. Работает только вместе с плагином Millennium [Window Styler (DWMX)](https://steambrew.app/plugin/b4c58634419b) и включёнными эффектами прозрачности Windows (Параметры → Персонализация → Цвета → «Эффекты прозрачности»). Как включить: поставить плагин в Millennium, включить его, перезапустить Steam. Тема узнаёт плагин по атрибуту `data-millennium-plugin~="dwmx"`, который Millennium ставит на окна; без плагина настройка ничего не меняет и остаётся обычный фон Mica.
- **«Что нового» на главной**, **Кнопка «Добавить новый раздел»**, **Строка адреса** — показывать или скрыть.
- **Раскладка** — «Как в Steam» или «Боковая панель». Во втором случае вторая строка шапки (назад/вперёд и вкладки Магазин, Библиотека, Сообщество, Профиль) уходит в узкую панель слева, вкладки получают значки, шапка становится в одну строку. Только CSS, без скриптов. Значки подбираются по порядку вкладок: где у Steam нет вкладки «Сообщество», значки после «Библиотеки» сдвинутся на одну.
- **Скруглённые углы** — да или нет. Скругления dev.txt: панель и карточка 8, строка, кнопка и подсказка 4.
- **Шрифт dev.txt** — Segoe UI Variable вместо шрифта Steam. Выключается, если где-то поехал текст.

Режим Big Picture тема не трогает. Светлой темы нет: Steam сам тёмный.

### Как тема держится за Steam

Классы в клиенте Steam хешированы (`._3x1HklzyDs4TEjACrRO2tB`) и меняются с обновлениями — поэтому темы и ломаются. Но в скриптах клиента (`<Steam>\steamui\*.js`) у каждого модуля стилей есть таблица `{PlayBar:"_2L3s2nzh7yCnNESfI5_dN1", SuperNav:"_2D64jIEK7wpUR_NlObDW76", …}`: читаемое имя из исходников Valve → хеш. Имена живут дольше хешей.

Поэтому в `theme/src` хешированный класс пишется именем:

| В исходнике | Значит |
|---|---|
| `.\@PlayBar` | класс `PlayBar`; во всём клиенте он должен быть ровно один |
| `.\@TopBar\@URLBar` | класс `TopBar` из того модуля, где есть и `URLBar` (`TopBar` есть в трёх модулях) |

Это обычный CSS — класс с именем `@PlayBar`, так что редакторы читают исходники как есть. `tools/build.js` подставляет хеши из [steam-classes.json](steam-classes.json) и пишет готовые `theme/*.css`. Неизвестное имя или имя без нужного уточнения — ошибка сборки; в ней перечислены варианты с подсказкой, каким именем уточнить:

```
theme/src/base.css:231: \@ToolTipTitle is ambiguous: 2 different classes; pick one:
      \@ToolTipTitle\@LifetimeQualityStats   module with ActiveHeader, Bar, BetaText, Center…
      \@ToolTipTitle\@ToolTipCustom   module with Center, TextToolTip, ToolTipCustom, ToolTipInsetContent…
```

Кроме хешей, тема опирается на то же, что и раньше: переменные самого Steam в `:root` (`--color-greyneutral-1…12`, `--color-blue-8`, `--radius-sm/md/lg`, `--font-family`), старые читаемые классы без хеша (`.DialogButton`, `.title-area-icon`, `.friend`, `.chatWindow`…) и классы, которые ставит Millennium (`html.MillenniumWindow_…`).

Специфичность правил темы повторяет специфичность правил Steam (их видно в `<Steam>\steamui\css`), поэтому `!important` стоит только там, где Steam задаёт свойство цепочкой, которую не перебить весом. Каркас главного окна тема перестраивает сама: список игр, основная область и нижняя панель — отдельные слои с зазором 8px на фоне Mica, содержимое главной, страницы игры и загрузок — карточки на этих слоях. Настройка «Боковая панель» дополнительно уводит вкладки в панель слева.

**После обновления Steam:**

```bash
npm run steam          # = node tools/steam-classes.js && node tools/build.js
node tools/check.js --steam
```

Первая команда снимает новый снимок с установленного клиента (папка Steam — из реестра, `HKCU\Software\Valve\Steam`, `SteamPath`; другую можно назвать: `node tools/steam-classes.js --steam <папка>`) и пересобирает тему. Если Valve переименовал или убрал модуль, сборка остановится и скажет, какое имя в `theme/src` поправить. Diff снимка читаемый: один модуль — одна строка. Снимок и собранные файлы коммитятся, так что для сборки Steam не нужен.

Вторая команда ничего не пишет: сверяет снимок в репозитории с установленным клиентом и печатает, какие из использованных темой имён пропали или стали другим хешем.

## Тема на основе Steam Enhanced

**Основано на [Steam Enhanced](https://github.com/NVHT/Steam-Enhanced) by NVHT (MIT).** Вторая сборка темы Arkada — их тема целиком с нашим слоем поверх. Лицензии — в [THIRD_PARTY.md](THIRD_PARTY.md).

| Что | Где |
|---|---|
| их код, как есть | [upstream/steam-enhanced](upstream/steam-enhanced) — копия их репозитория без `.git` и картинок README. **Руками не правится никогда** |
| наши правки их кода | [patches](patches) — unified diff к файлам `upstream/steam-enhanced`, каждый с описанием «что и зачем» (готово для PR им). Накладываются только на копию в `dist/arkada` |
| какая версия у нас | [upstream/steam-enhanced.json](upstream/steam-enhanced.json): `repo`, `ref` (тег), `commit`, `date` |
| наш слой | [overlay](overlay): `tokens.css` (их переменные `--se-…` значениями dev.txt и вид Windows 11), `win11.css` (Windows 11 там, где их CSS рисует своими значениями), `i18n.css` (их надписи из CSS по-русски), `i18n.js` (их надписи из скриптов по-русски), `nav.js` (смена страницы одним входом), `brand.css` (их брендинг убран), `backdrop.css` (окна насквозь, когда плагин Arkada включил подложку Windows), `options/`, `skin.json` (наши поля и настройки поверх их манифеста) |
| готовая тема | `dist/arkada` — собирается, в git не хранится |

```bash
npm run upstream          # = node tools/upstream.js: их последний релиз → upstream/steam-enhanced
node tools/upstream.js --ref 1.3.0   # конкретный тег или коммит
npm run upstream:check    # только сказать, вышло ли новее (код возврата 1, если да)
npm run build:se          # = node tools/build-se.js: upstream + overlay → dist/arkada
```

`tools/upstream.js` берёт последний релиз через GitHub API (релизов нет — голову ветки `main`), скачивает архив исходников, распаковывает и целиком заменяет `upstream/steam-enhanced`. Нужен только Node 22 и `tar` (есть и в Windows, и в Linux). С переменной `GITHUB_TOKEN` запросы к API идут от имени токена.

`tools/build-se.js` каждый раз собирает `dist/arkada` заново: их файлы (кроме `skin.json`, `README.md`, `assets/`; их `LICENSE` ложится как `LICENSE-steam-enhanced`), затем наш слой в `dist/arkada/arkada/`, затем `skin.json` — их манифест, слитый с `overlay/skin.json`:

- наше поле заменяет их; `null` убирает поле — так убраны `header_image`, `splash_image`, `github` и `RootColors`;
- `Patches` дописываются после их (их два патча запускают тему: `core/core.js` и `client/loader.js`);
- `Conditions` сливаются по имени: новые — впереди, их — поле за полем, значения так же (`null` убирает значение);
- версия — наша плюс их: `0.4.0+se.1.3.5`. Их загрузчик веб-страниц метит этой версией каждый файл, так что с их обновлением кеш страниц не путает сборки.

Сборка проверяет, что каждый файл, названный в `skin.json`, на месте, и при одном и том же входе пишет одно и то же.

**Почему убран `github`.** По этому полю Millennium узнаёт тему в своём каталоге: проверяет обновления, считает её установленной и обновляет из названного репозитория. С их `github` он считал бы Arkada их темой и предложил бы «обновить» её их версией поверх нашего слоя.

**Как их тема грузит стили и куда встаёт наш слой.** В `skin.json` у них только два скрипта на все окна. `client/loader.js` сам решает, что нужно окну, и вставляет все его стили одним `<style id="se-sheets">` из `@import` — уже после ссылок, которые ставит Millennium. Их переменные — на `:root` в `core/tokens.css`, их настройки (`options/…`) — на `:root:root`. Наш `arkada/tokens.css` подключён своим патчем (`".*"`, все окна) и пишет на `html:root`: это сильнее их значений по умолчанию при любом порядке загрузки и слабее их настроек — выбранные «Corners: Sharp» или «Font: Xmind» по-прежнему работают. В `arkada/tokens.css` сначала идёт `theme/tokens.css` (переменные `--dt-…`), потом `overlay/tokens.css`.

**Что из их брендинга убрано.** Заставка Splash и вход Logo (их знак) — из настройки «Window entrance», по умолчанию None: окно появляется сразу, как загрузилось, без затухания (Fade остаётся на выбор). Их знак в кнопке Steam в шапке — нейтральный значок из четырёх плиток; слово «Steam Enhanced» в шапке — «Arkada». Знак внутри индикаторов загрузки, логотип в окне «О Steam» и надпись на экране входа убраны, индикатор по умолчанию — простое кольцо. Шрифт по умолчанию — Segoe UI Variable; SN Pro, Xmind и Motiva Sans остаются на выбор. Их цветовой выбор (`RootColors`) заменён настройкой «Акцент» — теми же файлами `theme/options/accent-*.css`.

**Небольшие окна.** Тема делалась на 3440×1440; на 16:9 (1920×1080, 2560×1440, 1366×768, масштаб 125/150 %) то, что не помещается, убирается целиком, а не переносится на вторую строку (`overlay/win11.css`, раздел «Smaller windows»): вкладки страницы игры — одна строка, лишние в «⋯» (Steam считает место без вкладки «Обзор» и без промежутков, а свёрнутая вкладка у них была `display: none` и при пересчёте «помещалась» с шириной 0); цифры полосы «Играть» — один ряд, не поместившаяся пропадает; статус друга в списке — одна строка с «…»; подписи рейла друзей не шире рейла. Проверено эмуляцией размеров через CDP: одна строка вкладок, полоса 75 px, ни одного пересечения блоков страницы игры, в том числе при смене размера окна на открытой странице.

**Вид Windows 11.** Окно — Mica (`--dt-bg` с каплей акцента), страница — слой Fluent со скруглённым углом у панели, обводка 1px, скругления 8 у блоков и 4 у контролов. Главная кнопка («Играть», «Установить», «Скачать») — сплошной акцент без градиента и свечения; «Остановить» — критическая заливка Windows. Выделение — мягкая нейтральная заливка и акцентная полоска 3px (слева в списке игр и в рейле, снизу у вкладки страницы игры). Подписи без капса и разрядки, шрифт по шкале Windows (12 / 14 / 20 / 28, semibold). Акрил (размытие) — только у всплывающих меню, подсказок и тостов, полосы и плашки поверх картинок — обычные слои. Всё это — в `overlay/tokens.css` (их переменные) и `overlay/win11.css` (их правила со своими значениями).

**Смена страницы.** `overlay/nav.js` (свой патч `TargetJs`, только главное окно) слушает роутер Steam (`MainWindowInstance.m_history`) и ничего не задерживает: новая страница входит в том же кадре, в котором Steam её отрисовал (появление и подъём на 6px, `--dt-dur-fast`). Замер: страница игры видна через 60–240 мс после перехода, главная — через ~300 мс (столько Steam строит её сам), загрузки — ~230 мс. Страница игры устроена иначе: в момент перехода (тот же кадр) старая страница уходит и на её месте сразу стоит скелет — ровные плашки WinUI без мерцания: герой, полоса запуска, вкладки и две колонки блоков (для открытой раньше игры — по запомненным размерам, для новой — типовые). Под ним Steam невидимо строит настоящую страницу (`html[data-arkada-gp="hold"]`, `overlay/win11.css`), и она показывается одним кроссфейдом (~200 мс, `--dt-ease-out`), когда готова: картинка героя загружена, обложка и описание на месте (для известной игры — все запомненные блоки), колонки 120 мс не двигались; или по таймауту — 1,5 с для новой игры, 2 с для известной (известная ждёт, пока все запомненные блоки придут и дорастут до запомненной высоты ±10 %). Обложка заранее держит рамку 2:3, чтобы левая колонка не росла, когда приходит картинка. Раскладка обзора устойчивая (`0007-game-page-column-stacks.patch`): у каждого типа блока своя колонка и своё место в ней (`order` в их `layout.css`; слева — обложка, сведения, HLTB, друзья, обзор, контроллер, заметки, DLC, карточки, скриншоты, мастерская; справа — описание, метки, избранное, достижения, итоги, лента, сообщество), каждая колонка — стопка (`--se-row` — сумма высот блоков над ним, `--se-span` — его высота), места пишутся в колбэке ResizeObserver до отрисовки. Если после показа что-то ещё вырастет, блоки под ним в той же колонке съезжают (`transform`, `--dt-dur-base`), сам блок открывается вниз вместе с ними (`clip-path`), поздний блок проявляется с подъёмом на 6px (`--dt-dur-fast`); сдвиг читается из атрибута `style` (старая строка минус новая), ничего не измеряется. Цифры полосы запуска проявляются так же.

**Раскладка игры запоминается.** Через полторы секунды покоя (и при уходе со страницы) nav.js сохраняет прямоугольники блоков страницы игры относительно панели и общую рамку страницы — героя, полосу запуска, вкладки (`localStorage`, ключ `arkada.gamePage.v4`, последние 100 открытых игр; при другой ширине страницы, больше чем на 8px, сохранённое не берётся). По ним строится скелет при следующем открытии: он совпадает с готовой страницей, и кроссфейд почти незаметен. Знакомая игра показывается, как только блоки первого экрана (в пределах высоты панели) на месте и той же высоты (±5 %, не меньше 6px; блок, уходящий за низ экрана, — только до низа экрана; блок с другим содержимым — после 250 мс без сдвигов на экране); обложка, сведения, описание, метки и избранное, которые Steam монтирует только на ~1 с, не ждутся: их строки заранее держатся по запомненной высоте (`--se-hold-<колонка>`, патч 0007), и они проявляются на своём месте; то, что ниже экрана, может дорасти после показа и сдвигает только то, что под ним. При сниженной анимации (хаб, Windows, их «Animations: Reduced») скелет сменяется страницей без перехода, сдвиги не анимируются.

**Прогрев страницы игры.** Странице игры при первом открытии нужны данные приложения от Steam (`appDetailsStore.RequestAppDetails`, описание, связи, достижения) и картинки (герой, логотип, обложка). nav.js просит их заранее: когда курсор задержался 100 мс на игре (список библиотеки, полки главной, коллекции — appid берётся из props React-узла под курсором) и через 5 с после старта окна, в простое (`requestIdleCallback`), — 15 последних запущенных игр по одной с паузой 0,7 с, не пока строится страница игры. Картинки декодируются (`new Image().decode()`) по тем же адресам, что ставит Steam (свои картинки пользователя и картинки магазина). Каждая игра прогревается один раз за сессию, одна за раз.

**Надписи по-русски.** Их надписи из CSS (`content: '…'`) переводит `overlay/i18n.css`, надписи из их скриптов — `overlay/i18n.js` (свой патч `TargetJs`, все окна, только при русском клиенте: `<html lang>`, `LANGUAGE=` в адресе окна или язык системы). Один `MutationObserver` переводит текст их узлов (класс `se-…`; узлы Steam внутри их контейнеров не трогаются) и их атрибуты (`placeholder`, `title`, `aria-label`, `data-se-…`) — только при полном совпадении со словарём или шаблоном с числами (1 игра / 2 игры / 5 игр, «3,4 ч»). Названия игр, ники и сообщения остаются как есть. Если их код сам возвращает английский текст на место, узел после трёх таких возвратов оставляется по-английски, чтобы не мигать. `npm run check` проверяет, что файл разбирается и что каждая строка словаря ещё есть в их коде (пропавшие — предупреждение).

**Подложка окна.** Настройка «Подложка окна»: Акрил (по умолчанию: размытое то, что за окном, под всеми окнами, как в Discord), Mica (тонированные обои под главными окнами — по природе почти непрозрачная, серая) или Выкл. Её делает плагин Arkada (раздел «Подложка окна» в описании плагина), сторонний DWMX не нужен. Тема и плагин связаны через `<html>` каждого окна, в обе стороны: тема говорит, что нужно, — переменная `--arkada-backdrop: mica | acrylic | off` (`overlay/options/backdrop-mica.css`, `backdrop-acrylic.css`; при «Выкл» остаётся `off` из `overlay/tokens.css`); плагин отвечает, что получилось, — атрибут `data-arkada-backdrop="mica|acrylic"`, который он ставит, только когда Windows приняла подложку. Правила `overlay/backdrop.css` ждут этот атрибут. Тинт кладётся один раз, слои друг на друга не копятся (три тинта по 58 % пропускают меньше 8 % — окно снова непрозрачное): корень окна прозрачный; рамка окна Steam (`SteamUIPopupWindow`, первый ребёнок `body`) — лёгкий тинт `--arkada-tint` 30 % (у Mica 35 %): тёмный акрил Windows сам затемняет то, что за окном, и по токенам текст на нём поверх белых обоев — 9–13,5 : 1, вторая строка 6,6–9 : 1, третья 5 : 1; липкие полосы, под которыми прокручивается содержимое, — плотнее (`--arkada-cover` 72 %); в окнах с этой рамкой их грунт `--se-bg` прозрачный, а всё, что из него смешано (поверхности, наведение, поля), становится слоем Fluent — белым поверх прозрачного. Свои непрозрачные грунты Steam (`ForceOpaqueBackground`, `AppDetailsTransitionGroup`, тело страницы игры, полоса «Главная/поиск» над списком игр) очищены; затемнения, которыми картинки (шапка игры, сцена главной, загрузки, баннер коллекции) уходили в грунт, заменены маской на самой картинке. Липкие полосы, под которыми прокручивается содержимое, сохраняют свой тинт. В меню (`ContextMenuPopup`: окно больше меню, ради тени) рамки нет, и `--se-bg` остаётся тинтом; панели всплывающих меню (`--arkada-acrylic`) тоньше, под ними акрил. Проверено сканером по главной, страницам игр, загрузкам, коллекциям, доку друзей и меню: ни один элемент (с `::before`/`::after` и градиентами) не непрозрачнее 0.85 на площади от 4 % окна, и в сетке точек нет двух тинтов друг на друге. Без плагина атрибута нет и всё непрозрачно, как раньше. Нужны включённые эффекты прозрачности Windows (Параметры → Персонализация → Цвета).

**Проверки слоя.** `npm run check` проверяет и `overlay/`: цвета только из токенов и их смесей, каждый названный в `overlay/skin.json` файл есть. И что `upstream/steam-enhanced` не правили: `tools/upstream.js` записывает в `upstream/steam-enhanced.json` отпечаток папки (`digest`, `tools/se-digest.js`), проверка его пересчитывает.

**Патчи к их коду.** То, что нельзя сделать слоем поверх, правится патчем: `patches/NNNN-имя.patch` — сначала свободный текст (что и почему), затем diff в формате `git diff` (`--- a/путь` / `+++ b/путь` / `@@`). `tools/build-se.js` накладывает патчи по порядку имён на копию в `dist/arkada` (`tools/patches.js`: ханк ставится туда, где его контекст и удаляемые строки стоят как есть, ближайшее к названной строке место, без нечёткого совпадения). Если после их обновления патч не накладывается, сборка и `npm run check` падают с именем патча, файла и ханка — патч надо обновить под их новый код или убрать, если они исправили сами; PR от workflow это покажет. Патчи: `0002-game-page-scroll-frame.patch` — на странице игры кадр прокрутки больше не читает размеры (кнопка «наверх»: при прокрутке только прогресс, сначала чтения, потом записи; скроллер без кнопки не ищется заново); `0003-runtime-poll-in-frame.patch` — проверки `SE.poll` идут в начале кадра, а не из таймера, и `checkVisibility` не вызывает лишний пересчёт стилей всего окна; `0001-loader-menu-bundle.patch` — в окне меню их загрузчик берёт один файл стилей (`core/menu.bundle.css`, `core/menu-tray.bundle.css`; собирает `tools/build-se.js` из их файлов в порядке списка загрузчика, каскад тот же) вместо ~30 `@import`. Steam открывает каждое меню в новом окне, а окно рисуется, только когда пришли все его стили (`blocking="render"`). Проверено в 12 окнах меню: вычисленные стили всех элементов совпадают с исходными, файл приходит за 6–14 мс. Меню открываются и закрываются за половину `--dt-dur-fast` (~83 мс, `overlay/win11.css`) вместо 167 мс. `0004-nav-rail-has-subject.patch` — обёртки кнопок шапки (`.tool-tip-source`) их правила ищут по классу (`:where(.tool-tip-source):has(…)`), а не одним `:has()`: каждая раскладка главного окна стала вдвое дешевле (страница CS2: 560 → 297 мс раскладки за те же 27 проходов). `0006-game-page-span-unknown-height.patch` — `fit()` их раскладки не ставит блоку span 1, пока не знает его высоту, если у блока уже есть span (иначе обложка и описание на ~1,2 с вставали на строку в 1px поверх соседей, и все блоки колонок уезжали вверх и обратно). `0007-game-page-column-stacks.patch` — каждая колонка страницы игры — стопка: вместо автоматической расстановки (`grid-auto-flow: row dense`), которая при каждом росте блока переставляла блоки в освободившиеся места, `fit()` ставит каждому блоку его строку (`--se-row`) — сумму высот блоков над ним в его колонке, в том же кадре, что и новую высоту. `0005-has-invalidation-scope.patch` — 21 правило в 11 файлах переписано без `:has()` над составным селектором без класса/атрибута (`A:has(B) > *`, `A:has(B) > :not(.c)`): у Blink один набор инвалидации на `:has()` на всё окно, и одно такое правило делало его «всем поддеревом» — при каждом изменении DOM, которое могло задеть аргумент `:has()`, стиль пересчитывался у всего окна (страница CS2: пересчётов всего `<body>` 20 → 0, элементов 37 880 → 8 419, стиль 1,7 → 1,2 с). Вычисленные стили всех элементов страницы игры, главной и загрузок совпадают до и после; три переписанных правила (строки настроек, «Свойства» ярлыка) опираются на разметку Steam, как её рисует sp.js — это сказано в патче. `0008-home-collections-card-width.patch` — карточка коллекции на доске главной не уже 160 px: на доске уже 1300 px панель «Коллекции» в половину ширины брала 4 карточки в ряд (на 1920×1080 названия обрезались до 68 px, на 1366×768 — до трёх букв); теперь колонок столько, сколько помещается, остальное — за «+N». `0009-dock-fold-at-1600.patch` — док друзей сворачивается в рейл на окнах до 1600 px (было 1400): окно 1600×900 и экран 1920×1080 при масштабе 125 % оставляли странице ~900 px. `0010-hltb-ask-arkada-first.patch` — карточка How Long To Beat спрашивает время сначала у плагина `arkada`, потом у плагинов HLTB, как раньше.

**Как приходят их исправления.** Workflow [.github/workflows/upstream.yml](.github/workflows/upstream.yml) раз в неделю (и по кнопке, можно с тегом) запускает `tools/upstream.js`. Если версия у них другая, он собирает `dist/arkada`, гоняет `npm run check` и тест плагина и открывает PR «Steam Enhanced <тег>» со ссылкой на их сравнение коммитов (`compare старый...новый`). В PR — только `upstream/`. Сливает человек, предварительно поставив тему и посмотрев глазами: наш слой держится за их имена переменных, класс `.se-list-brand-word` и названия настроек, и если у них что-то из этого поменялось, это видно только в Steam (переименованные файлы настроек поймает сборка).

**Установка:**

```bat
robocopy dist\arkada "<Steam>\millennium\themes\arkada" /MIR
```

Новые `Patches` Millennium применяет только после полного перезапуска Steam. Затем выбрать Arkada в настройках Millennium, раздел «Темы».

| **Цены инвентаря и итоги рынка** | в инвентаре — цена каждого предмета на Торговой площадке и стоимость открытой игры; в истории операций рынка — сколько всего куплено и продано | Augmented Steam |
| **Кнопка «Поделиться»** | на странице игры в магазине, рядом с «В желаемое» и «Подписаться», — кнопка с меню: «Копировать ссылку» и «Отправить другу в Steam…» (выбор друзей с поиском, ссылка уходит в личные сообщения Steam) | Steam Share |

**Как настройка доходит до плагина.** Так же, как «Подложка окна»: `overlay/tokens.css` ставит на `<html>` всех окон `--arkada-kapsula`, `--arkada-disk-size`, `--arkada-hltb`, `--arkada-share`, `--arkada-dota`, `--arkada-prices`, `--arkada-game-info`, `--arkada-hide-owned`, `--arkada-wishlist-sum`, `--arkada-market` со значением `on`, файл настройки `overlay/options/feature-*-off.css` — `off`. Плагин (`features.js`) раз в 2 секунды читает их в главном окне и запускает или останавливает модуль; последний ответ помнит в `localStorage` (`arkada.features`), чтобы при следующем запуске функция работала сразу. Если главного окна нет (Steam свёрнут в трей) и ответа не было 10 секунд — действует запомненное, иначе включено. Файлы «Выкл» к тому же сразу прячут уже нарисованное (`[data-arkada-disk-size]`, `[data-arkada-hltb]`, `#arkada-share`, `#arkada-dota`, `#arkada-prices`, `#arkada-game-info`, `#arkada-wishlist-sum`, `#arkada-inventory-value`, `.arkada-inv-price`, `#arkada-market-history`), не дожидаясь плагина. Функции страниц магазина и сообщества страница проверяет сама: читает `--arkada-<функция>` у своего `<html>` при открытии (`web.js`) и при «Выкл» ничего не спрашивает и не рисует. Скрытие купленного — правило стиля, которое страница ставит при открытии: выключение действует со следующей открытой страницы.

**Быстродействие.** Модуль работает только там, где нужен. Kapsula — только соединение и общий с хабом перехват уведомлений (один на весь плагин: `steam.watchToasts`), одна подписка на загрузки (`steam.watchDownloadOverview`). Размер на диске — только в главном окне и только на странице игры: маршрут берётся у роутера Steam (`MainWindowInstance.m_history.listen`, ничего не стоит между переходами), а наблюдатель DOM (`watch.js`: `MutationObserver` на `<body>`, только списки детей, не чаще раза за кадр, в `requestAnimationFrame`) подключается при входе на страницу игры и отключается при уходе с неё. Если элемент уже на месте, проход — одна проверка. Размеры спрашиваются у Steam при открытии страницы игры, не чаще раза в 5 секунд. «Поделиться» — только в страницах магазина и только на странице игры; раскладка читается только по нажатию (куда открыть меню), прокрутка меню закрывает. Время прохождения — на тех же страницах и тем же наблюдателем, что размер на диске; бэкенд спрашивается один раз на игру за час (ответы он хранит на диске днями), а с темой Steam Enhanced модуль только включает бэкенд — карточку рисует тема. Статистика Dota 2 — только на странице самого профиля (`/id/<имя>/`, `/profiles/<id>/`, не на его подстраницах); наблюдатель DOM нужен, только пока не появилась правая колонка. «Цены» и «Об игре» — только на странице игры в магазине, с одним наблюдателем `watch.js` на страницу (пока карточка на месте, проход — одна проверка `isConnected`; тема может перерисовать свою сводку — карточка возвращается). Скрытие купленного — одно правило стиля, без наблюдателя и без чтения страницы. Сумма списка желаемого и итоги рынка — без наблюдателя: лёгкий таймер раз в 1,5–2 секунды проверяет, на месте ли карточка (React перерисовывает шапку). Цены инвентаря — без наблюдателя: раз в 1,5 секунды одно сравнение, какой инвентарь открыт; запросы — очередью, по одному, пока страница видна. Ни один модуль не читает раскладку в кадрах прокрутки.

**Kapsula.** Модуль — перенос плагина Kapsula (MIT, см. [THIRD_PARTY.md](THIRD_PARTY.md)) с тем же протоколом: `ws://127.0.0.1:42071/?client=millennium`, сообщения `hello`, `toast` (`kind, eType, title, body, icon, steamid, url, game, appid, invite, extra`), `download` (`appid, name, state, paused, percent, rate, eta`), `replied`, `error`; команды `config { hideToasts }`, `test`, `dismissInvite`, `openChat`, `reply`. Через хаб dev.txt Kapsula уведомления Steam не получает, поэтому модуль говорит с ней напрямую. Пока в Steam загружен сам плагин Kapsula (`PLUGIN_LIST.kapsula`), модуль молчит — уведомление не придёт дважды. Если Kapsula попросила прятать всплывающее окно Steam (`hideToasts`), модуль прячет его, пока она подключена, и никогда — в игре. **Папку плагина Kapsula удалять нельзя:** Kapsula открывает свой порт только когда есть `<Steam>\millennium\plugins\kapsula\plugin.json`; достаточно выключить плагин в Millennium.

**Размер на диске.** Данные — `SteamClient.InstallFolder.GetInstallFolders()`: то, что Steam сам знает о папках библиотеки на этом компьютере (сеть не нужна, папки не обходятся). Для ярлыков не из Steam размера там нет, и он не показывается. Рисуется классами самой строки статистики Steam (`GameStat`, `GameStatIcon`, `PlayBarLabel`…): их находит `MILLENNIUM_API.findClassModule`, а если не нашёл — снимок `steam-classes.json` (`plugin/src/steam-snapshot.js`). В списке и сетке библиотеки размера нет: плагин Size on Disk там его тоже не показывает, а у Steam есть своя сортировка по размеру.

**«Поделиться».** Кнопка — того же вида, что кнопки Steam в этом ряду (`.queue_control_button > .btnv6_blue_hoverfade`), поэтому её рисует тема. Меню и диалог — Windows 11 на токенах dev.txt (`plugin/src/tokens.js` из `theme/tokens.css`; акцент — `--se-accent` темы, если он есть на странице), значки — Segoe Fluent Icons. Ссылка — чистая, `https://store.steampowered.com/app/<id>/`. Список друзей и отправку делает часть плагина в клиенте: страница зовёт её через `MILLENNIUM_API.callable("arkada", "frontend:arkadaShare.friends" | "frontend:arkadaShare.send")`, а клиент отправляет сообщение тем же вызовом, что Kapsula для ответа другу (`ChatStore.GetFriendChat(…).SendChatMessage`). После отправки ссылка ещё и копируется в буфер обмена. Избранного и перетаскивания друзей, как в Steam Share, нет.

**Время прохождения.** Данные — с howlongtobeat.com; это единственная функция плагина, которая сама ходит в интернет, и только пока её настройка включена (`HltbSetup { on }`; выключенный бэкенд на каждый вопрос отвечает `{ success: false, error: "off" }` без запроса). Запросы делает бэкенд на Lua (`require("http")` Millennium, поэтому CORS не мешает) — перенос кода плагина HLTB for Steam 2.2.0 (MIT, см. [THIRD_PARTY.md](THIRD_PARTY.md)). У HLTB нет открытого API, адрес поиска и токен меняются, поэтому их ищут на ходу: главная страница → `_buildManifest.js` (или скрипты `_next/static/chunks`) → путь `/api/…`, у которого есть пара `…/init` (сейчас `/api/search/site`); `GET …/init?t=<мс>` → `token`, `hpKey`, `hpVal` (живут 5 минут) → `POST` поиска с `x-auth-token`, `x-hp-key`, `x-hp-val`; время игры по её номеру HLTB — `_next/data/<buildId>/game/<id>.json`. Не ответил поиск или токен — адрес ищется заново, один раз. Номер HLTB для игры Steam: из импорта библиотеки HLTB (`api/steam/getSteamImportData`, только для открытого профиля; раз в неделю на пользователя), из таблицы `arkada_hltb_ids.lua`, иначе поиск по английскому названию из магазина Steam (`store.steampowered.com/api/appdetails?l=english`: в клиенте названия бывают русскими) — точное совпадение, затем ближайшее по Левенштейну с проверкой номера Steam у трёх лучших, затем ещё раз без хвостов вроде «Definitive Edition». Ответы хранятся в `<Steam>\millennium\arkada-hltb-cache.json` (рядом с плагином, а не в его папке: переустановка их не стирает): найденная игра свежая 7 дней, ненайденная — сутки, потом показывается старое и спрашивается заново; обновление раньше суток после прошлого запроса отвечается из кэша — один запрос на игру. Карточку Steam Enhanced (`compat/hltb-for-steam`) кормит тот же вызов `GetHltbData(app_id, fallback_name, force_refresh)` с тем же ответом, что у HLTB for Steam; патч `0010-hltb-ask-arkada-first.patch` учит её спрашивать сначала `arkada`, а её английские подписи переведены в `overlay/i18n.js`. Без темы Steam Enhanced — строка «Время прохождения» `42,5 ч · 60 ч · 105 ч` классами строки статистики Steam (как размер на диске), подсказка с названиями этапов, по нажатию — страница игры на howlongtobeat.com в браузере (`SteamClient.System.OpenInSystemBrowser`). Бэкенд Lua однопоточный: пока он ждёт HLTB (первый запрос к игре — несколько секунд), подложка нового окна ждёт вместе с ним.

**Статистика Dota 2.** Данные — с api.opendota.com, открытого бесплатного API без ключа (60 запросов в минуту). Страница профиля спрашивает его сама (OpenDota отвечает странице `steamcommunity.com` заголовками CORS; проверено): `players/<id>`, `…/wl`, `…/wl?date=365`, `…/heroes`, `…/peers` и раз в неделю список героев `heroes`; ответы — в `localStorage` страницы на 6 часов. Номер игрока — младшие 32 бита SteamID64 из `g_rgProfileData` страницы. Карточка — Windows 11 на токенах dev.txt, картинки героев — с CDN Valve. Если у игрока нет открытых матчей (не играл или скрыл их в настройках Dota 2), карточки нет. Плагин Dota 2 Stats берёт данные у прокси своего автора к STRATZ (ранг с медалью и примерный MMR, роль по линиям, Dota Plus); здесь — только OpenDota, без медалей, MMR и ролей. Код Dota 2 Stats не взят: карточка написана заново по тому, что он показывает.

**Функции Augmented Steam и SteamDB.** Пять настроек вкладки «Arkada» повторяют полезное из браузерных расширений Augmented Steam и SteamDB. Их код не взят (у Augmented Steam GPL, см. [THIRD_PARTY.md](THIRD_PARTY.md)) — всё написано заново на открытых интерфейсах, в виде карточек Windows 11 на токенах dev.txt. С темой Arkada (Steam Enhanced прячет колонки Steam на странице игры и рисует свою сводку) карточки «Цены» и «Об игре» встают вверху правой колонки этой сводки, без темы — вверху области покупки и правой колонки Steam.

- **Цены (`prices.js`, `arkada_itad.lua`).** «История цен на SteamDB» — просто ссылка на `steamdb.info/app/<id>/#pricehistory`, без запроса; рядом — ссылка на игру на IsThereAnyDeal (`isthereanydeal.com/steam/app/<id>/`). Лучшая цена сейчас и исторический минимум — IsThereAnyDeal API v2, у которого **все запросы цен требуют ключа** (проверено: без ключа `403 Missing api key`; без ключа работает только поиск номера игры `lookup/id/shop`, цен он не даёт). Ключ личный и бесплатный: приложение регистрируется на <https://isthereanydeal.com/apps/my/>. Вводится он в самой карточке («Добавить ключ» → поле → «Сохранить»; там же «Удалить ключ») и уходит не в страницу, а в бэкенд: тот хранит его в `<Steam>\millennium\arkada-itad.json` (рядом со Steam, не в папке плагина и не в репозитории) и сам спрашивает `api.isthereanydeal.com` (заголовок `ITAD-API-Key`): `POST lookup/id/shop/61/v1` `["app/<id>"]` → номер игры (хранится 30 дней), `POST games/overview/v2?country=<страна магазина>` → `current` (магазин, цена, скидка, ссылка `itad.link` — как её дал ITAD) и `lowest` (магазин, цена, дата). Ответы — в `<Steam>\millennium\arkada-itad-cache.json` на 6 часов на игру и страну (игра без цен — на сутки); не больше 60 запросов за 5 минут (ITAD разрешает 1000). Страна — `country_code` пользователя из `#application_config` страницы. Без ключа в интернет ничего не уходит, карточка показывает ссылки, подсказку, что даст личный ключ IsThereAnyDeal, и «Добавить ключ». Ключ не принят — «IsThereAnyDeal не принял ключ». Вызовы бэкенда из страницы — `Millennium.callServerMethod("arkada", "ItadPrices" | "ItadKey", …)` (он есть на страницах магазина, проверено).
- **Об игре (`gameinfo.js`).** Часы (всего и за две недели), последний запуск и «На аккаунте с» — из библиотеки клиента: страница спрашивает часть плагина в клиенте (`MILLENNIUM_API.callable("arkada", "frontend:arkadaGame.info")`), та читает `appStore.GetAppOverviewByAppID(id)` (`minutes_playtime_forever`, `minutes_playtime_last_two_weeks`, `rt_last_time_played`, `rt_purchased_time` — когда лицензия пришла на аккаунт). Без сети. Игры нет в библиотеке — только ссылки на SteamDB, PCGamingWiki (`pcgamingwiki.com/api/appid.php?appid=<id>`) и ProtonDB.
- **Скрывать купленное и игнорируемое (`hideowned.js`).** Магазин сам помечает элементы своих списков: у каждого, который можно свернуть, есть `.ds_collapse_flag`, и скрипт Steam (`GDynamicStore`, данные о владении на странице) добавляет `.ds_owned` или `.ds_ignored`. Arkada ставит одно правило — `display: none` этим элементам. Без сети и без наблюдателя. Не работает на странице игры, набора и комплекта (там список DLC — что у вас есть, видно нарочно) и в списке желаемого. Где Steam не ставит этих пометок (части новых страниц на React, например главная магазина), ничего не скрывается.
- **Сумма списка желаемого (`wishlist.js`).** Открытый Web API Steam, тот же, что у самой страницы (отвечает `store.steampowered.com` с CORS, проверено): `IWishlistService/GetWishlist/v1?steamid=<владелец>` → игры, `IStoreBrowseService/GetItems/v1` по 100 игр за запрос → `best_purchase_option` в стране магазина (`final_price_in_cents`, `original_price_in_cents`, `discount_pct`). Владелец списка — из данных страницы (`SSR.loaderData`). Ответ — в `localStorage` страницы на 30 минут. Показывает сумму сейчас, без скидок, экономию и сколько игр со скидкой; без цены — не вышедшие и бесплатные. Закрытый список — карточки нет.
- **Цены инвентаря (`inventory.js`).** На странице инвентаря (`/id/<имя>/inventory`, `/profiles/<id>/inventory`) — предметы открытой игры из объектов самой страницы (`g_ActiveInventory`, его `m_rgAssets` с описаниями; у инвентаря Steam — его части `m_rgChildInventories`), только те, что можно продать. Цена — `market/priceoverview` Торговой площадки (то же, что показывает окно продажи), самая низкая сейчас (`lowest_price`, иначе `median_price`), в валюте кошелька (`g_rgWalletInfo.wallet_currency`), по одному запросу на вид предмета: **не чаще раза в 1,5 секунды**, по одному, только пока страница видна; Steam ответил 429 — пауза минута, затем вдвое дольше, до 10 минут. Цены хранятся в `localStorage` страницы сутки — повторное открытие спрашивает только новое. Цена — значком на плитке предмета, сумма (цена × количество) — карточкой над инвентарём, с тем, сколько ещё оценивать. Большой инвентарь Steam догружает по мере листания: считается то, что он уже загрузил. Ничего не продаётся и не выставляется.
- **Итоги рынка (`markethistory.js`).** На странице истории операций (`/market/history`) — карточка под вкладками. По кнопке «Посчитать» (до неё страница ничего не читает) — `market/myhistory/render` по 100 строк за запрос, не чаще раза в 2 секунды; строка «+» — покупка, «−» — продажа, выставления и снятия не считаются. Итоги («Куплено», «Продано», «Продано минус куплено», сколько раз) хранятся сутки и показываются сразу, с кнопкой «Пересчитать». Суммы — цены, как их показывает история Steam.

### Подложка окна

Окна Steam прозрачные, под ними системная подложка Windows 11 — без стороннего плагина DWMX. Какая — решает настройка темы «Подложка окна» (см. раздел темы): плагин читает `--arkada-backdrop` через `getComputedStyle` у `<html>` окон клиента (своей страницы и всех окон `g_PopupManager`) раз в 2 секунды; первое окно с ответом решает. Последний ответ помнится в `localStorage` (`arkada.backdrop`): окна, которые при запуске открываются раньше, чем загрузилась тема, создаются уже по нему. Ни одно окно не ответило за 30 секунд — темы Arkada нет, режим «Выкл».

Пока режим не «Выкл»:

- `window.open` подменён, как у DWMX: в адресе окна `createflags=4114` и `createflags=2` становятся `274` — окно создаётся с прозрачной поверхностью. Другие значения и адреса без параметра не меняются. При «Выкл» адреса проходят как есть;
- бэкенд `ApplyBackdrop` вызывается полным проходом (все окна) при старте и при смене режима; для нового окна — проходом «только новые» (`{ only: 'new' }`: уже обработанные окна не трогаются) через 60 мс после `window.open` или появления окна в `g_PopupManager`, а через 400 и 1500 мс — только если в предыдущий раз ничего нового не нашлось (окно ещё не показано); и каждый раз, когда окно Steam выходит на экран (`visibilitychange` его документа: меню Steam создаёт скрытыми заранее и показывает без `window.open`);
- когда бэкенд ответил `ok`, на `<html>` всех окон ставится `data-arkada-backdrop="mica|acrylic"` (кроме окна Big Picture); тема становится прозрачной только по нему.

Бэкенд (`plugin/backend/main.lua`) находит процессы `steamwebhelper.exe`, перебирает их видимые окна и делит на главные (не tool window, от 480×320) и малые (меню, всплывающие, маленькие окна). Big Picture (по заголовку) и окна во весь монитор без рамки пропускаются. На Windows 11 22H2+ (сборка 22621 и выше): `DWMWA_USE_IMMERSIVE_DARK_MODE` = TRUE, `DWMWA_WINDOW_CORNER_PREFERENCE` (ROUND / ROUNDSMALL), `DWMWA_SYSTEMBACKDROP_TYPE` (2 — Mica у главных окон в режиме Mica, 3 — Acrylic у остальных и у всех в режиме «Акрил»), `DwmExtendFrameIntoClientArea` с полями −1. На более старых сборках или если атрибут 38 не принят — размытие accent через `SetWindowCompositionAttribute`, как у DWMX. «Выкл» и выгрузка бэкенда возвращают окнам подложку по умолчанию. Проход дешёвый: список процессов `steamwebhelper.exe` кешируется на 10 с (сразу обновляется, если у запомненных не осталось окон), заголовок читается `InternalGetWindowText` — без сообщения окну, которое как раз занято открытием; окно, ушедшее во весь экран после обработки, замечает полный проход. Каждое применение пишется в лог Millennium (`<Steam>\millennium\logs\arkada_log.log`), например `hwnd 0x… main mica: dark=0x00000000 corner=0x00000000 backdrop(2)=0x00000000 frame=0x00000000`, а каждый проход, который что-то применил, — со своим временем: `new-window pass: 14 window(s), 1 patched, 13 kept, 0 failed in 0.84 ms (63 ms after the window opened)`.

Подложка и подмена `window.open` начинают действовать после полного перезапуска Steam: бэкенд Millennium подхватывает только при запуске, а окна, созданные до подмены, остаются непрозрачными до следующего открытия.

### Что уходит в хаб

Плагин подключается к хабу как приложение `arkada` по адресу `ws://127.0.0.1:42080/hub`. **В хаб и через хаб с компьютера ничего не уходит:** это соединение локальное. Наружу ходят только функции, каждая пока включена её настройка: время прохождения (howlongtobeat.com и магазин Steam), статистика Dota 2 (api.opendota.com), цены IsThereAnyDeal (api.isthereanydeal.com, только с ключом), сумма списка желаемого (api.steampowered.com), цены инвентаря и итоги рынка (steamcommunity.com/market) — см. «Функции вместо отдельных плагинов». Хаба нет — плагин молча пробует снова через 1, 2, 4… до 15 секунд.

Состояния (хаб их помнит):

| Тема | Данные |
|---|---|
| `arkada.game` | `{ appId, name, since }`, пока игра запущена; иначе `null`. `since` — время запуска, миллисекунды |
| `arkada.downloads` | `{ appId, name, progress, bytesPerSecond, paused }`; `progress` от 0 до 1. Ничего не качается — `null` |
| `arkada.friends` | `{ online, inGame }` — сколько друзей в сети и сколько из них в игре. Сверяется раз в 15 секунд |
| `arkada.settings` | четыре переключателя для страницы настроек core.txt |

События (хаб их не помнит). Берутся из всплывающих уведомлений Steam — если Steam решил уведомление не показывать, события нет:

| Тема | Данные |
|---|---|
| `arkada.achievement` | `{ appId, game, title, text, icon }` |
| `arkada.invite` | `{ steamid, from, game, appId, text, icon, url }` — кто зовёт и в какую игру; `url` — адрес входа `steam://…` |
| `arkada.message` | `{ steamid, from, text, icon }` |

Команды:

| Команда | Что делает |
|---|---|
| `game.launch { appId }` | запускает игру |
| `library.open` | открывает библиотеку |
| `invite.accept { steamid }` или `{ url }` | принимает последнее приглашение от этого друга либо открывает адрес входа из события |
| `settings.set { key, value }` | меняет переключатель; незнакомый ключ — `"ok": false` |

Настройки (ключ — надпись):

- `shareGames` — «Показывать игры другим приложениям dev.txt». Выключено: `arkada.game` пуст, достижения не сообщаются.
- `shareDownloads` — «Показывать загрузки».
- `shareInvites` — «Показывать приглашения».
- `shareMessages` — «Показывать сообщения». Выключено: событие `arkada.message` не отправляется.

Настройки хранятся в `localStorage` страницы Steam под ключом `arkada.settings`.

Плагин следит за `hub.theme`: общий акцент экосистемы попадает в тему через переменную `--arkada-hub-accent` на `<html>` каждого окна клиента, «меньше движения» — через атрибут `data-arkada-motion`. Светлый режим из `hub.theme` не применяется. На страницы магазина акцент из хаба не действует — туда плагин не дотягивается.

## Сборка

```bash
node tools/build.js ../kit.txt/tokens/tokens.json
```

Берёт токены kit.txt, обновляет их копию [tokens.json](tokens.json) и пишет `theme/tokens.css` и файлы акцентов в `theme/options`. Без пути — собирает из копии. `theme/tokens.css` совпадает с `kit/dist/tokens.css` байт в байт.

Той же командой собираются стили: каждый `theme/src/…/X.css` → `theme/…/X.css` с хешами из [steam-classes.json](steam-classes.json) и строкой «Сгенерировано… Руками не править» в начале. Steam для этого не нужен.

```bash
node tools/steam-classes.js [--steam <папка Steam>]
```

Читает `<Steam>\steamui\*.js` и пишет [steam-classes.json](steam-classes.json): версию и дату клиента (из `package\steam_client_win64.manifest`) и все модули стилей — у каждого только хешированные классы, ключи по алфавиту, модули в постоянном порядке. В Steam ничего не пишет. `npm run steam` — снимок и сборка подряд.

```bash
node plugin/build.js
```

Пишет `plugin/dist/arkada/plugin.json` и `plugin/dist/arkada/.millennium/Dist/index.js`. Обёртка вокруг кода — та же, что у плагина Kapsula.

Файл `.star` — по желанию, для него нужен компилятор Millennium. Он ставится только в папку `plugin`:

```bash
cd plugin
npm install
npm run build:star
```

Получается `plugin/dist-star/arkada.star` и рядом `bundle.js` — скрипт, вынутый обратно из этого файла. Бэкенд `backend/main.lua` входит в `.star` (раздел `[backend]` в `millennium.toml`); комментарии starlight вырезает, поэтому уведомление об источнике (DWMX, Apache-2.0) продублировано в строке `NOTICE`, которая пишется в лог при загрузке. Файла `LICENSE-dwmx` в `.star` нет — он есть в папочной сборке и в репозитории. Файл не подписан: подпись ставит только Millennium при публикации в своём каталоге.

## Релиз

```bash
npm run package
```

Запускает `node tools/build-se.js` (тема → `dist/arkada`) и `node plugin/build.js` (плагин → `plugin/dist/arkada`), затем пишет в `release/` (папка в `.gitignore`):

- `arkada.zip` — архив для установщика в core.txt (его он и скачивает); рядом `arkada-<версия>.zip` с теми же байтами;
- `arkada.zip.sha256` и `arkada-<версия>.zip.sha256` — sha256 архива, hex;
- `latest.json` — `{ version, file, sha256, size }` (core.txt он не нужен: sha256 тот берёт из GitHub API).

Тег релиза на GitHub — `v<версия>`. Версия берётся из `plugin/plugin.json` (в `package.json` то же число; у темы в `skin.json` есть ещё суффикс `+se…`). Архив собирается самим скриптом `tools/package.js` без зависимостей: файлы по алфавиту, дата 1980-01-01, поэтому два запуска дают один и тот же sha256.

Внутри архива:

- `theme/` — содержимое `dist/arkada`;
- `plugin/` — содержимое `plugin/dist/arkada` (`.core-version` в архив не кладётся);
- `manifest.json` — core.txt читает из него только `activeTheme`, `enablePlugin` и `replaces` (`size-on-disk`, `steam-share`, `kapsula`, `extendium`; имена латиницей). Остальное — для справки: `name`, `version`, `theme` и `plugin` (`folder`, `installTo`: `millennium/themes/arkada`, `millennium/plugins/arkada`), `keepFolders` (`kapsula` — её папку не удалять: Kapsula открывает порт, только пока есть её `plugin.json`), `minMillennium` (сейчас `null`: с какой версии Millennium Arkada работает, неизвестно);
- `THIRD_PARTY.md` и `LICENSE` (если в корне есть).

Как ставит core.txt: скачивает `arkada.zip` из GitHub Releases, сверяет sha256, раскладывает `theme/` и `plugin/` по `installTo` внутри папки Steam, убирает папки заменённых плагинов из `replaces` (кроме `keepFolders`), включает тему и плагин в `millennium/config/config.json` (`activeTheme`, `enablePlugin`) и перезапускает Steam.

## Установка вручную

Папка Steam записана в реестре: `HKCU\Software\Valve\Steam`, значение `SteamPath`. Обычно это `C:\Program Files (x86)\Steam`. Millennium должен быть уже установлен — тогда в папке Steam есть папка `millennium`.

**Плагин.** Скопировать папку `plugin\dist\arkada` целиком в `<Steam>\millennium\plugins`, чтобы получилось:

```
<Steam>\millennium\plugins\arkada\plugin.json
<Steam>\millennium\plugins\arkada\.millennium\Dist\index.js
<Steam>\millennium\plugins\arkada\.millennium\Dist\webkit.js
<Steam>\millennium\plugins\arkada\backend\main.lua
```

Перезапустить Steam и включить Arkada в настройках Millennium, раздел «Плагины». Вместо папки можно положить один файл `<Steam>\millennium\plugins\arkada.star` — но не то и другое сразу.

**Тема.** Скопировать папку `theme` под именем `arkada` в папку тем Millennium:

```
<Steam>\millennium\themes\arkada\skin.json
```

Так устроен нынешний Millennium. Его документация и старые версии называют другую папку — `<Steam>\steamui\skins\arkada\skin.json`. Ставить нужно туда, где у вас уже лежат темы. Затем выбрать Arkada в настройках Millennium, раздел «Темы».

## Как лаунчеру понять, что Arkada установлена

| Что узнать | Как |
|---|---|
| Есть ли Millennium | существует папка `<Steam>\millennium` (так же проверяет Kapsula) |
| Стоит ли плагин | существует `<Steam>\millennium\plugins\arkada\plugin.json` либо `<Steam>\millennium\plugins\arkada.star` |
| Версия плагина | поле `"version"` в этом `plugin.json` |
| Стоит ли тема | существует `<Steam>\millennium\themes\arkada\skin.json` либо `<Steam>\steamui\skins\arkada\skin.json` |
| Версия темы | поле `"version"` в этом `skin.json` |
| Работает ли плагин прямо сейчас | в `hub.apps` есть приложение `arkada` — это единственный надёжный признак |

По файлам нельзя понять, включён ли плагин и выбрана ли тема: это Millennium хранит в своих настройках, и человек включает их сам.

Экспорт `arkadaGame` части в клиенте проверен в Steam подменой (новый `index.js` грузится после перезапуска).

- **`localStorage`** в странице Steam: что настройки переживают перезапуск Steam, не проверено.
- **Переподключение к хабу внутри Steam.** В проверках оно работает и с WebSocket, который ведёт себя как в браузере, и с собственным WebSocket Node; в самом Steam не наблюдалось.
- **Настоящий хаб в core.txt.** Проверки шли против образцового `kit/hub/hub.js`.

## Правила

Arkada следует правилам kit.txt: цвета, радиусы и длительности — только из токенов; работает без хаба и без остальных приложений; всё наружу — только через хаб; сгенерированное руками не правится. Исключение — функции, которым нужны чужие сайты: время прохождения (howlongtobeat.com), статистика Dota 2 (api.opendota.com), цены IsThereAnyDeal (только с ключом пользователя), сумма списка желаемого и цены Торговой площадки (Steam). Ходят туда они сами, каждая только пока включена её настройка.
